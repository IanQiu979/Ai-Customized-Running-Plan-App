# Comprehensive app audit and fix pass — 2026-08-09

Scope: every reachable screen under `src/`, the shared plan engine, every app API route and D1
statement under `workers/`, environment/deployment configuration, the dead Supabase scaffold's
live import status, build/type/lint/test gates, and dependency health. Google sign-in files were
explicitly excluded because another parallel lane owns them.

## Temporary full-access mode

`workers/src/access.ts` is the single, reversible control point. The committed non-secret Worker
variable `ALL_USERS_UNLIMITED_ACCESS = "true"` currently makes every authenticated account Elite
and bypasses quota refusal/counting while preserving the subscription, purchase, and quota-ledger
implementation underneath. Set it to `"false"` in both Wrangler environments before real users
arrive. Settings and Home clearly report “Unlimited plans during the test pass.”

## Bugs found and fixed

1. **Web was completely unable to call the Worker.** Added credential-safe, exact-allowlist CORS,
   including preflight handling and headers on auth/API responses (`workers/src/cors.ts`).
2. **Web `/api/*` calls crashed before fetch.** The Expo auth plugin was handed SecureStore on web,
   where its sync implementation does not exist. Web now uses a no-op plugin adapter and browser
   cookies with `credentials: 'include'`; native keeps SecureStore and manual cookie replay.
3. **Paid/unlimited access was not comprehensive.** One server-side override now affects tier,
   plan density, quota status, atomic reservation, settlement, paywall visibility, and fallback
   quota copy without altering purchase flows.
4. **Fallback plans could display a false quota claim.** The server now returns/stores whether the
   specific plan consumed quota, and the plan screen selects the correct `FallbackNotice` variant.
5. **A failed generation retry could be permanently stuck.** A terminal released idempotency key
   now causes Home to mint a fresh key; network retries still preserve the original key safely.
6. **Generated Expo route types were stale, so a clean typecheck failed.** `npm run typecheck` now
   regenerates SDK-54 typed routes first via `scripts/generate-router-types.js`.
7. **Race request validation accepted malformed dates, unknown distances, fractional durations,
   and unbounded idempotency keys.** Worker validation now rejects all of them before reservation.
8. **Intake validation was incomplete.** It now rejects non-object bodies, impossible dates,
   unknown distances, zero/invalid times, contradictory `none + injury` arrays, invalid notes,
   and oversized free text with readable 400s.
9. **Intake client validation accepted fractional/out-of-range ages, negative distance, invalid
   clock values, and zero-second performances.** Client checks now match server/database rules.
10. **The D1 age constraint still allowed age 10 despite the app-wide floor being 13.** Updated the
    fresh schema and added migration `0003_intake_age_floor.sql` for existing databases.
11. **A server-revoked session left the app in an authenticated shell.** Any authoritative 403
    `unauthenticated` API response now clears better-auth's local session cache immediately.
12. **Dynamic plan routes could call the API with a missing/array id.** The screen now normalizes
    and rejects absent IDs instead of requesting `/api/plans/undefined`.
13. **Expo patch version was below the SDK-54 doctor requirement.** Updated Expo to 54.0.36;
    `expo-doctor` is clean.
14. **Fixable dependency advisories remained.** Safe lockfile-only audit updates removed all Worker
    advisories and reduced root findings; remaining root advisories require an Expo SDK 57 or other
    breaking major change and were not force-upgraded in an SDK-54 app.

- **Stock app art, Apple sign-in, and built-app deep-link verification:** existing launch/release
  work requiring product/account/device access, not code defects this isolated lane can finish.
